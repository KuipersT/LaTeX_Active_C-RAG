\section{Problem Formulation}\label{sec:prob_form}

\input{figures/system.tex}

In the state-of-the-art reviewed in Section~\ref{sec:background}, the evidence used to gauge factuality of the subclaims is retrieved before the subclaims are generated. Therefore, a true subclaim whose evidence was not retrieved has no way of being validated, and will be removed from the final set \eqref{eq:filter_set}. In this work, we seek to alleviate this issue by allowing the system to operate in rounds: at each round, based on the current subclaims, it either stops and answers, or it retrieves further evidence and then revises the subclaims. This effectively integrates active RAG~\cite{jiang2023active,asai2024selfrag} with CF and C-RAG~\cite{mohri2024language,cherian2024large} with the aim of producing larger, and thus more informative, certified filtered sets \eqref{eq:filter_set}.

As illustrated in Figure~\ref{fig:system}, the system answers a query $x$ over rounds $t = 0, 1, \ldots, T$, for a budget $T$ that is fixed in advance. At round $t$, it holds the subclaims $\hat{y}_t$ and the evidence $D_t$. Round $0$, shown in black, implements the same steps as C-RAG~\cite{feng2025response}, as described in Section~\ref{sec:background}, whereas the rounds $t \geq 1$, highlighted in blue, are added by the proposed system.

As in C-RAG, an LLM writes the claim $y$ using the query $x$ and the initial retrieved evidence $D_0$. Moreover, subclaim extraction is performed by another LLM that splits $y$ into the subclaims $\hat{y}_0 = \{c_1, c_2, \ldots\}$. The evidence $D_0$ is also placed into an evidence store, which holds the evidence $D_t \subseteq \mathcal{K}$ collected up to round $t$. As we will define, AC-RAG leverages the data $D_t$ so as to update its subclaims, producing set $\hat{y}_t$.

Generalising the C-RAG score \eqref{eq:crag_score}, at each round $t$, a subclaim scorer assigns a score $s_t(c \mid x, D_t)$ to every subclaim $c \in \hat{y}_t$ based on the query $x$ and on the current retrieved evidence $D_t$, and we write $s_t = \{ s(c \mid x, D_t) : c \in \hat{y}_t \}$ for the scores of all subclaims of set $\hat{y}_t$. The scores $s_t$ are used by a decision block to determine whether to stop at the current round $t$, passing the current subclaims $\hat{y}_t$ to the final filtering block, or to continue and revise the current claims. In this case, the subclaims $\hat{y}_t$ are then partitioned into three subsets
\begin{equation}
  (k_t, w_t, z_t) = \mathrm{Dec}(\hat{y}_t, s_t)
\end{equation}
with $k_t \cup w_t \cup z_t = \hat{y}_t$, and where subset $k_t$ contains the subclaims that are kept intact for the next round, $w_t$ the subclaims that are to be potentially reworked, and $z_t$ encompasses the subclaims in $\hat{y}_t$ to be discarded. We denote as $t^{*}$ the stopping time. Both the partition and the decision to stop may depend on a set of hyperparameters, which we collect in a vector $\lambda$.

Whilst the system has not stopped, using the subclaims $w_t$, a new retrieval query $q_t(x, w_t, D_t)$ is produced as function of the input query $x$, the subclaims $w_t$ and the current evidence $D_t$, and the documents returned for these queries are added to the evidence store as
\begin{equation}
  D_{t+1} = D_t \cup \mathrm{Retrieve}\bigl(q_t(x, w_t, D_t)\bigr).
  \label{eq:store}
\end{equation}
Using the updated evidence $D_{t+1}$, the subclaims $w_t$ are reworked into a generally different number of subclaims using an LLM, yielding the set 
\begin{equation}
  \hat{y}_{t+1} = k_t \cup \mathrm{Rev}(x, w_t, D_{t+1}).
\end{equation}

At the end of the round $t^{*}$, the final filtering block applies a filter like \eqref{eq:filter_set} to the remaining subclaims $\hat{y}_{t^*}$, with a threshold that is calibrated on a calibration set of $n$ labelled queries $(x, y^{*})$, each of which has been processed by the same loop. For any fixed $\lambda$, this gives the guarantee \eqref{eq:cf}, regardless of how the loop behaves, since the calibration queries and the new query receive the same treatment. However, \eqref{eq:cf} alone does not ensure that the returned set is useful, as it is also satisfied by small or empty sets. We therefore also measure the quality of the set $\hat{y}_{\lambda}(x)$ returned with hyperparameters $\lambda$ by a loss $L(\hat{y}_{\lambda}(x), x) \in [0, 1]$, e.g., one that is large when the returned set is small or does not answer the query, and define the risk
\begin{equation}
  R(\lambda) = \mathbb{E}\bigl[ L(\hat{y}_{\lambda}(x), x) \bigr],
  \label{eq:risk}
\end{equation}
where the expectation is taken over the query $x$ and the system. The goal is to select hyperparameters $\lambda$ for which the risk \eqref{eq:risk} is at most a target level $\varepsilon$, while keeping the guarantee \eqref{eq:cf}.
